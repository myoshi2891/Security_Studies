0.3 学習の全体像

STEP 1. ISO/IEC 18045:2026 を一言でいうと

1.1 一言での説明

「Common Criteria(ISO/IEC 15408)で製品を評価するとき、評価者は最低限何をどう確認しなければならないか」を定めた規格です。

ISO の公式ページの要旨(Abstract)によると、この規格は ISO/IEC 15408 シリーズの評価基準と評価証拠を使って評価を行うために、評価者が実施する要件と最低限のアクションを規定しています確認済。

たとえ話をすると次のようになります。

たとえ 対応する規格
運転免許の試験項目表(何ができれば合格か) ISO/IEC 15408(Common Criteria)
試験官向けの採点マニュアル(どう確認し、どう判定するか) ISO/IEC 18045(CEM)

つまずきポイント: ISO/IEC 18045 は「製品がどうあるべきか」を直接定める規格ではありません。評価する人(評価者)の作業手順と判定の考え方を定める規格です。

STEP 2. なぜ「評価方法の規格」が必要なのか

2.1 歴史を知ると目的が分かる

atsec information security(Common Criteria 評価で国際的に知られる評価機関)の解説記事によると、Common Criteria は各国で別々に作られていた評価基準が統合されて生まれました確認済。

2.2 「基準」だけでは足りない理由

評価基準(ものさし)だけがあっても、評価者ごとに確認の深さや判定がバラバラだと、次の問題が起きます。

問題 具体例
評価結果が比較できない A社の評価機関では合格、B社の評価機関では不合格
国をまたいだ相互承認ができない 日本で取得した認証書が海外で信頼されない
開発者が準備できない 何の証拠をどの程度用意すれば良いか分からない

そこで、評価者が最低限やるべきことを共通化する規格として CEM(= ISO/IEC 18045)が存在します。国際相互承認の枠組み(CCRA)の下で、各国の認証制度が同じ水準で評価結果を受け入れるための土台になっています一般知識。

2.3 CEM の著作権と ISO 版の関係

2026年版の序文(Introduction)によると、CEM は複数の政府機関が共同で著作権を保有しており、ISO/IEC に対して ISO/IEC 18045 の継続的な開発・保守のために CEM を使用する非独占的ライセンスを許諾しています。政府機関側は CEM を使用・複製・配布・翻訳・改変する権利を保持しています確認済(ANSI公式プレビュー)。

STEP 4. 登場人物と役割

4.1 評価に関わる主な役割

2026年版の序文では、主な読者は ISO/IEC 15408 を適用する評価者と、評価者の作業を確認する認証者(certifier)とされています。副次的な読者として、評価スポンサー、開発者、PP・PP-Module・PP-Configuration・ST の作成者、その他 IT セキュリティに関心のある方が挙げられています確認済。

役割 英語 主な責任 根拠
スポンサー Sponsor 評価を依頼し、必要な証拠の提供を取りまとめる 一般知識
開発者 Developer ST、設計文書、ソース、テスト証拠などの評価証拠を用意する 一般知識
評価者 Evaluator CEM に従って評価アクティビティを実施し、判定する 確認済
認証者 Certifier 評価者の作業が CEM に沿っているか確認し、認証判断に使う 確認済

4.2 スキームの役割がなぜ重要か

序文には、この規格は IT セキュリティ評価に関するすべての疑問に答えるものではなく、追加の解釈が必要になり得ること、そうした解釈の扱いは個々のスキームが決めるが、相互承認協定の対象になり得ることが書かれています。スキームが扱い得る方法論関連の活動の一覧は Annex A に載っています確認済。

4.3 評価の一般的なやり取り

用語: ITSEF = IT Security Evaluation Facility(評価機関)、OR = Observation Report(所見報告書)、ETR = Evaluation Technical Report(評価技術報告書)。OR と ETR の作成は 18045 の章構成で「評価出力タスク」の一部として登場します確認済(目次の 8.5.4 と 8.5.5)。

5.3 評価者の判定(Evaluator verdicts)

18045 には「評価者の判定」を扱う節(8.2.5)があります確認済(目次)。判定の対象は ISO/IEC 15408 シリーズの評価者アクション要素であり、work unit の実施結果は判定そのものではなく、その判定の根拠として扱われます一般知識。CEM の判定は一般に次の3種類です一般知識。

判定 意味 開発者への影響
pass 要求を満たし、かつ証拠に一貫性があると評価者が判断 次へ進める
fail 要求を満たしていない、または証拠に不整合や明白な矛盾があると評価者が判断 修正が必要
inconclusive まだ判断できない(証拠が不足、確認待ちなど) 追加の証拠や説明が必要

CEM では、下位の判定が積み上がって上位の判定になる構造をとります。基本的な考え方は「すべての下位判定が pass のときだけ上位も pass」です一般知識。

9.2 CC 側の要素と CEM 側の work unit

一般知識CC Part 3 の各コンポーネントは、次の3種類の要素(element)から成ります。CEM は、このうち評価者アクション要素を、さらに具体的な work unit へ分解します。加えて、評価者アクション要素の多くは「提供された情報が内容・提示の要求を満たすことを確認する」ものであるため、開発者アクション要素(D)や内容・提示要素(C)の要求も、その確認を通じて work unit の派生元になります。

要素 記号 誰が何をするか
Developer action elements D 開発者が提供しなければならないこと
Content and presentation elements C 提供される証拠が含むべき内容と表現
Evaluator action elements E 評価者が行わなければならないこと

序文によれば、この文書は必須の評価アクティビティに関する特別な動詞を太字の斜体で示します確認済。第5章「Verb usage」はその動詞の使い方を定めています確認済:章題。

読むときのコツは次のとおりです筆者整理。

読み方のコツ 具体的な意味

STEP 11. EAL と評価の深さ

11.1 EAL とは

EAL(Evaluation Assurance Level)は、保証要件を段階的にまとめた定義済みパッケージです。ISO/IEC 15408-5 に定義されています確認済:パッケージが Part 5 にあること(atsec による CC:2022 の概要では、Part 5 に CC 3.1 R5 の EAL1〜7 と CAP が含まれると説明されています)。

EAL 一般的な呼び名 一言でいうと
EAL1 Functionally tested 機能テストした
EAL2 Structurally tested 構造的にテストした
EAL3 Methodically tested and checked 体系的にテストし確認した
EAL4 Methodically designed, tested and reviewed 体系的に設計・テスト・レビューした
EAL5 Semiformally designed and tested セミフォーマルに設計しテストした
EAL6 Semiformally verified design and tested セミフォーマルに設計を検証しテストした
EAL7 Formally verified design and tested フォーマルに設計を検証しテストした

一般知識上記は一般的な呼び名です。EAL が高い = 製品が安全ではなく、「セキュリティ機能の保証を確認した深さが深い」という意味です。

11.2 EAL と CEM の関係

つまずきポイント: EAL の「plus(+)」は、EAL の標準パッケージに追加または強化したコンポーネントがあることを示します一般知識。

STEP 17. よくある質問と誤解

質問・誤解 回答
ISO/IEC 18045 を読めば製品のセキュリティ要件が分かる? いいえ。要件の中身は ISO/IEC 15408(特に Part 2 と Part 3、および PP や ST)にあります。18045 は評価者の作業を定めます
開発者は 18045 を読まなくてよい? 序文では開発者は副次的な読者です。ただし、評価者が何を見るかを知ると、証拠の準備の質が上がります
CC 認証を取れば製品は安全? 認証は、ST に書かれた主張が評価された範囲で確認されたことの証明です。範囲外の安全性は保証しません一般知識
EAL が高いほど良い製品? EAL は確認の深さであり、製品の優劣ではありません。用途と PP の要求で適切な水準が決まります
2026年版が出たので今すぐ全部切り替わる? いいえ。各スキームがいつ採用するかは別です(STEP 13.3 参照)
ISO/IEC 27001 と何が違う? 27001 は組織の ISMS、CC は製品の評価です(STEP 3.4 参照)

STEP 20. 確認できなかった点と注意事項

項目 状況 推奨する対応
2026年版の work unit ごとの差分 公開情報では確認できず 規格本文とCEM:2022の差分を直接比較する
規格本文の詳細(第9章から第17章の全文) 公式プレビューは序文と目次まで ISO の Online Browsing Platform や購入版で確認する
CCRA の 2026年相当版の公開時期 取得したページでは CC:2022 Release 1 が現行表示 CC ポータルとスキームの最新通知を確認する

一般知識タグの記述 2026年版の全文では再確認していない 実務で使う前に規格本文で確認する
